# Migration guide: `@zama-fhe/sdk` 3.0.0-alpha.32 → 3.1.0-alpha.5

> Generated from the deterministic diff bundle
> (`llms-full.txt` + API-report diffs + changelog) between `v3.0.0-alpha.32`
> and `v3.1.0-alpha.5`. This is the frozen, reviewed artifact that the
> `apply-migration-guide` step follows. The machine-readable source of truth is
> the companion `.json`; this file is for human review.

The changes are **idempotent**: applying a change that an app already satisfies
is a no-op. This matters because an app's `package.json` pin can lag its source
(e.g. `react-viem` already uses `createConfig` and `useDelegationStatus({ contractAddress })`
while still pinning `alpha.32`). Apply the whole guide regardless of the pin.

## Headline

The dominant change is in **`@zama-fhe/react-sdk`**: mutation hooks dropped the
`config: UseZamaConfig` object in favour of a positional `address`, and query/config
interfaces renamed their `tokenAddress` field to `address`. The core
`@zama-fhe/sdk` package replaced the `Handle` type with `EncryptedValue` (hex),
reshaped `EncryptResult` to contract-ready hex, removed `ReadonlyToken`, and
renamed `createZamaConfig` → `createConfig`.

## Required changes

### React hooks: config object → positional `address`

`useConfidentialSetOperator`, `useConfidentialTransferFrom`, `useDelegateDecryption`,
`useFinalizeUnwrap`, `useResumeUnshield`, `useRevokeDelegation`, `useToken`,
`useUnshield`, `useUnshieldAll`, `useUnwrap`, `useUnwrapAll` no longer take a
`{ tokenAddress, wrapperAddress? }` object as the first argument — they take the
token `address` directly.

```diff
- useUnshield({ tokenAddress, wrapperAddress: tokenAddress }, { onSuccess })
+ useUnshield(tokenAddress, { onSuccess })

- useDelegateDecryption({ tokenAddress }, { onSuccess })
+ useDelegateDecryption(tokenAddress, { onSuccess })
```

For ERC-7984 the wrapper _is_ the token, so the now-redundant `wrapperAddress` is dropped.

### React object-config hooks: `tokenAddress` → `address`

`UseConfidentialBalanceConfig`, `UseConfidentialBalancesConfig` (`tokenAddresses` → `addresses`),
`UseConfidentialIsOperatorConfig`, `UseConfidentialTransferConfig`, `UseShieldConfig`,
`UseUnderlyingAllowanceConfig` renamed their token field to `address`.

```diff
- useShield({ tokenAddress, wrapperAddress: tokenAddress }, { onSuccess })
+ useShield({ address: tokenAddress }, { onSuccess })

- useConfidentialTransfer({ tokenAddress }, { onSuccess })
+ useConfidentialTransfer({ address: tokenAddress }, { onSuccess })
```

`UseDelegationStatusConfig.tokenAddress` → `contractAddress` (separate field name).

### React renames

- `useDelegatedUserDecrypt` → `useDelegatedDecrypt` (`DelegatedUserDecryptMutationParams` → `DelegatedDecryptMutationParams`)
- `useAllow` → `useGrantPermit`; `useIsAllowed` → `useHasPermit`; `UseIsAllowedConfig` → `UseHasPermitConfig`
- `useReadonlyToken` → `useWrappedToken` (returns `WrappedToken`)
- `UseZamaConfig` interface **removed**

### React signature / return changes

- `useUserDecrypt(config: UserDecryptQueryConfig)` → `useUserDecrypt(encryptedInputs: EncryptedInput[])`
- `useEncrypt()` now returns the hex `EncryptResult` object, not `{ handles: Uint8Array[]; inputProof: Uint8Array }`

### React removed hooks (no drop-in replacement)

`useCreateEIP712`, `useCreateDelegatedUserDecryptEIP712`, `useGenerateKeypair`,
`usePublicKey`, `usePublicParams`, `useRequestZKProofVerification` were removed
(auto-signer resolution moved inside the high-level hooks — see #281). Re-express
via the high-level hook flow.

### Core `@zama-fhe/sdk`

- `Handle` type **removed** → `EncryptedValue` (= `Bytes32Hex`). Contract builders
  (`confidentialTransferContract`, `unwrapContract`, `finalizeUnwrapContract`,
  `write*Contract`, …) now take `EncryptedValue` / `Hex` instead of `Uint8Array`.
- `EncryptResult` reshaped from `InputProofBytesType` to a contract-ready hex object (SDK-200).
- `ReadonlyToken` **removed**: `Token` is standalone; `WrappedToken extends Token`.
- `buildZamaConfig` and `buildRelayer` **removed** from the public API.
- `createZamaConfig` → `createConfig` (entry points `/viem`, `/ethers`, `react-sdk/wagmi`).
- **`ZamaSDK` capability refactor.** `sdk.requireSigner(op)` was removed — use the
  `sdk.signer` property with a null guard instead:
  ```diff
  - const signer = sdk.requireSigner("mint");
  + const signer = sdk.signer;
  + if (!signer) throw new Error("A wallet signer is required to mint");
  ```
  Flat methods (`allow`, `isAllowed`, `userDecrypt`, `delegateDecryption`, …) moved
  under `sdk.decryption` / `sdk.delegations` / `sdk.permits`; `createReadonlyToken`
  → `createToken` / `createWrappedToken`.

## Recommended changes

- Transport factories: rename the `relayer` parameter to `options`.
- `resolveChainTransports` is now 2-arg (the `chainIds` argument was removed).
- New capability-grouping classes `Decryption`, `Delegations`, `Permits` are available (additive; no migration required).

## Per-app notes

These are not part of the reusable guide — they are what the `apply` step would
report after running against a given app.

- **`react-viem`** (current source): already satisfies `createConfig` and
  `useDelegationStatus({ contractAddress })`. Remaining work is the config→address
  hook migration in `ShieldCard`, `TransferCard`, `UnshieldCard`,
  `PendingUnshieldCard`, `DelegateDecryptionCard`, `RevokeDelegationCard`. Its core
  imports (`balanceOfContract`, `clearPendingUnshield`, `loadPendingUnshield`,
  `DelegationNotFoundError`, `ViemProvider`, `ViemSigner`) are unchanged A→B.
