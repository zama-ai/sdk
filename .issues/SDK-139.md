## Why

Docs lag implementation by design throughout this epic — every prior sub-issue explicitly excludes documentation changes. That is correct during construction (it avoids documenting a half-shipped API) but unsustainable after. Once the credentials surface is stable, consumers need a single coherent description of how it works. Without this sub-issue the docs site silently misrepresents shipped behavior.

## What

A single pass over all consumer-facing documentation that reflects the credentials API as shipped through the foundation, widening, KMS-context recovery, and derivationSecret wrapping sub-issues.

### In scope

- Docs site pages for `allow`, `allowAs`, `userDecrypt`, `userDecryptAs`, `isAllowed`, `revokePermits`, `clearCredentials`, identity-change semantics.
- The storage strategy: delegated security model, how to target different backends, the `derivationSecret` option for headless contexts.
- READMEs in `packages/sdk` and `packages/react-sdk` where they reference removed types or old config keys.
- Example apps that imported `CredentialsManager` / `DelegatedCredentialsManager` or removed config keys.
- `AGENTS.md` notes if they describe the old credentials machinery.

### Architectural constraints

- **Documentation describes the model first, methods second.** The keypair-vs-permission separation is the headline.
- **No API changes here.** Purely descriptive. If a documentation gap reveals a missing method or unclear contract, file it as a separate follow-up.

## How

1. Audit `*.md` and docs sources for references to removed types and config keys: `CredentialsManager`, `DelegatedCredentialsManager`, `BaseCredentialsManager`, `keypairTTL`, `sessionTTL`, `sessionStorage`, `StoredCredentials`, `DelegatedStoredCredentials`. Replace or remove every occurrence.
2. Add or rewrite a "Credentials" page on the docs site that explains: keypair (identity-scoped, chain-independent) vs. permissions (chain + delegator-scoped, 1-to-many), `permitDuration`, the lifecycle verbs (`allow`, `revokePermits`, `clearCredentials`) and what each preserves vs. wipes, the storage strategy and `derivationSecret` option.
3. Update `packages/sdk/README.md` and `packages/react-sdk/README.md` where they reference removed types or old config keys.
4. Update `AGENTS.md` if it describes the old credentials machinery.
5. Walk every example app that imports credential-related code; rebuild and verify.
6. Run linkcheck across docs site.
